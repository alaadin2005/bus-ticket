# نشر Bus Ticket Booking System على 3 خوادم

## توزيع الأدوار

- `db01` — CentOS Stream 9 — MySQL — عنوان قاعدة البيانات `192.168.3.15`
- `app01` — CentOS Stream 9 — Java/Tomcat 9 — عنوان التطبيق `192.168.3.12`، ومصدر اتصال قاعدة البيانات المتوقع `192.168.3.21`
- `web01` — Ubuntu 22.04 — Nginx — `192.168.3.11`

مسار الطلب: المتصفح → `web01:80` → `app01:8080` → `db01:3306`.

## قبل البدء

1. خذ Snapshot/نسخة احتياطية للـ VMs، خصوصًا `db01`.
2. شغّل كل سكريبت على الـ VM الصحيح فقط وبصلاحية root.
3. تحتاج الخوادم إلى الوصول إلى الإنترنت لتنزيل الحزم والمستودع.
4. سكريبت قاعدة البيانات يستورد `database.sql` فقط إذا لم تكن هناك جداول موجودة في `ticketing_system`. إذا كانت القاعدة تحتوي على جداول، يتخطى الاستيراد لتجنب تكرار البيانات.
5. سكريبت `db01` و`app01` يطلبان كلمة مرور مستخدم التطبيق. استخدم كلمة المرور نفسها في الاثنين. لأجل سلامة كتابة ملف الخدمة، يدعم السكريبت كلمة مرور من 12 إلى 128 حرفًا من المجموعة `A-Z a-z 0-9 . _ -`. لا تضع كلمة المرور في أوامر shell أو في المحادثة.
6. هذه السكريبتات لا تمسح قاعدة البيانات ولا تحذف بيانات قائمة.

## التنفيذ بالترتيب

### 1) على db01

انقل `01-db01-setup.sh` إلى `db01` ثم:

```bash
chmod +x 01-db01-setup.sh
sudo ./01-db01-setup.sh
```

يتحقق السكريبت من MySQL، يبدأ الخدمة، ينزّل المشروع للحصول على `database.sql`، يستورد البيانات إذا كانت القاعدة فارغة، ويمنح `ticketapp` صلاحيات محدودة على `ticketing_system` من عنوان المصدر `192.168.3.21` فقط.

### 2) على app01

```bash
chmod +x 02-app01-setup.sh
sudo ./02-app01-setup.sh
```

يثبت Java 17 وTomcat 9، ينزّل المشروع، يعدل `Database.java` ليقرأ إعدادات الاتصال من متغيرات البيئة، يترجم ملف الاتصال، وينشر صفحات JSP وملفات classes وJDBC driver داخل Tomcat.

### 3) على web01

```bash
chmod +x 03-web01-setup.sh
sudo ./03-web01-setup.sh
```

يثبت Nginx ويضبطه كـ reverse proxy إلى `http://192.168.3.12:8080`.

## الاختبارات

على `app01`:

```bash
systemctl status tomcat --no-pager
curl -I http://127.0.0.1:8080/
journalctl -u tomcat -n 100 --no-pager
```

على `web01`:

```bash
nginx -t
curl -I http://192.168.3.12:8080/
curl -I http://127.0.0.1/
```

من جهاز العميل افتح:

`http://192.168.3.11/`

## ملاحظات مهمة

- هذه عملية نشر أولية وليست إعدادًا إنتاجيًا كاملًا؛ أضف HTTPS، نسخًا احتياطية مجدولة، وتدوير كلمات المرور قبل الاستخدام الفعلي.
- المشروع قديم، وملف SQL من MariaDB 10.1 مع ترميز `latin1`؛ اختبر الوظائف بعد الاستيراد.
- سكريبت التطبيق يعتمد على توفر حزم `java-17-openjdk-devel` و`tomcat9` و`mysql` في مستودعات CentOS المفعّلة. إذا لم يتوفر اسم حزمة Tomcat في مستودعات VM، أوقف التنفيذ وأرسل رسالة الخطأ بدل تثبيت إصدار عشوائي.
- نشر الكود من المستودع العام لا يعني أن التطبيق اجتاز مراجعة أمنية. لا تعرض Tomcat مباشرة على الإنترنت؛ استخدم Nginx أمامه.
- إذا فشل التشغيل، راجع أولًا `journalctl -u tomcat -n 100 --no-pager` و`/var/log/nginx/bus-ticket-error.log`.
